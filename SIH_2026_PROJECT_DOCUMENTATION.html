1. EXECUTIVE SUMMARY

The Sovereign Industrial AI Workbench is a complete, air-gapped on-premise operational intelligence and safety platform engineered for manufacturing plants, thermal power stations, chemical refineries, aerospace hangars, and national critical infrastructure.

In heavy industrial environments, operational telemetry and proprietary equipment documentation cannot leave the factory perimeter. Transmitting sensitive operational parameters over the public internet to commercial cloud AI providers (OpenAI, Anthropic, AWS Bedrock) violates strict security mandates (ISO/IEC 27001, IEC 62443, ITAR) and creates catastrophic intellectual property and cyber-warfare exposure.

The Sovereign Dual-Rail Breakthrough: Our workbench decouples the system into two isolated operational rails:
  • Cognitive Rail (Probabilistic AI): Offline quantized neural models (Qwen2.5-0.5B via llama_cpp), dense vector RAG (embedded Qdrant), causal GraphRAG, and LangGraph multi-step task planning.
  • Safety Rail (Deterministic Mathematics): Hard mathematical safety interlocks, physics-based threshold trip curves, automated E-Stop circuits, and a mandatory Two-Person Rule human approval gate before any physical machine command can execute.
The entire system runs 100% locally on on-premise hardware with zero cloud dependencies.

3. DEEP DIVE: THE SOVEREIGN MODEL GATEWAY

The Model Gateway (backend/app/ai/gateway.py) is the unified intelligence nexus of the Sovereign AI Workbench. Operating under the Facade Pattern, it provides a standardized, single point of entry for all generative, conversational, embedding, reranking, and classification requests.

Core Architectural Guarantee: Sub-agents and API routes never call underlying model drivers directly. The Model Gateway intercepts every request, executes pre-inference security checks, queries the Silicon Router for hardware limits, invokes local inference, redacts credentials from the output, and cryptographically commits the event to the HMAC audit ledger.

3.1 The 6-Stage Model Gateway Request Lifecycle

   └── If Malicious ➔ Instantly BLOCKS, logs security event to HMAC ledger, returns safe refusal
   │
   ▼ (Prompt Passed)
[ Stage 2: Intent & Task Classification ]

4. DEEP DIVE: HARDWARE-AWARE DYNAMIC SILICON ROUTER

The Hardware-Aware Router (backend/app/hardware/router.py) solves the critical challenge of industrial silicon heterogeneity. Industrial plants operate varied hardware—from low-power rugged laptops in electrical substations to high-end multi-GPU workstations in central control rooms.

The router evaluates runtime silicon constraints in real time, applies strict safety margins to protect host OS stability, evaluates candidate models in the catalog, and deterministically selects the optimal model using a multi-factor mathematical scoring function.

4.1 The 4 Dynamic Hardware Tiers

Tier Identifier Hardware Thresholds Target Industrial Environment Active Execution Mode
TIER 1 (LOW CPU) Dual-core CPU, ≤ 12GB RAM, Integrated GPU Rugged field laptop, portable substation IPC 0.5B GGUF on CPU or Native Deterministic Fallback
TIER 2 (MID CPU) 6-8 core CPU, 16-32GB RAM, Integrated GPU Standard plant maintenance workstation 1.5B – 3B GGUF models on multi-threaded CPU
TIER 3 (GPU DESKTOP) Dedicated GPU (4-12GB VRAM), RTX 3050/4060, Apple M2 Engineering design room, CAD workstation 7B – 8B GGUF models with CUDA / Metal offloading
TIER 4 (ENTERPRISE SERVER) Enterprise GPU (16-24GB+ VRAM), A10G, A100 Central plant data center, multi-unit control room 14B – 70B GGUF models with full GPU acceleration

4.2 Safe Memory Budget Mathematical Formulation

To eliminate host Out-Of-Memory (OOM) lockups on industrial machines, the router computes memory ceilings before loading any model weights:

Max Safe RAM Budget  = min( max(0.75, Available_RAM * 0.85, Available_RAM - 0.5), Total_RAM * 0.70 )
Max Safe VRAM Budget = max( 0.0, (Available_VRAM * 0.80) - 0.5 )

4.3 Multi-Factor Model Scoring Algorithm

Candidate models are scored on a 100-point scale balancing capability, memory headroom, task affinity, and hardware acceleration:

Total Score = Base_Score (50.0)
            + Task_Affinity_Bonus   (+25.0 for primary match, +12.0 for secondary match)
            + Model_Capacity_Factor (min(25.0, Parameters_in_Billions * 7.5))
            + Headroom_Bonus        (min(15.0, (Safe_RAM - Required_RAM) / Safe_RAM * 15.0) for CPU, or +20.0 for GPU)
            + Priority_Modifier     (Catalog_Priority * 0.08)
Fail-Safe Fallback Guarantee: If local GGUF models are absent or memory is exhausted, the router instantly selects the Sovereign Native Deterministic Reasoner (0.4 GB RAM, 0 MB disk). It evaluates mathematical thresholds (95°C, 7.5 mm/s, 25 ppm gas) directly in memory, ensuring 100% operational uptime under extreme hardware degradation.

5. SUBSYSTEM TECHNICAL SPECIFICATIONS

📡 1. Live Telemetry & Digital Twin
High-frequency telemetry simulator generating realistic harmonic physics (temperature, vibration, current, gas). Streams live JSON ticks every 1.5s via WebSockets (/ws/telemetry/) to dynamic SVG charts.
🏭 2. 3D Plant Floor "God View"
Spatial Three.js WebGL canvas displaying machinery, overhead cranes, and safety fences. Machine shaders dynamically update colors (Green = Normal, Yellow = Warning, Red = Critical) based on live health scores.
🚨 3. Deterministic Safety Engine
Mathematical threshold engine 100% isolated from the LLM. Instantly evaluates telemetry against safety rules. Triggers immediate automated machine state transitions to SHUTDOWN if safety limits are breached.
🛡️ 4. Two-Person Rule Approval Gate
Physical machine commands proposed by an operator or AI agent are suspended in a pending queue. Execution is blocked until a certified SAFETY_OFFICER inspects the rationale and provides digital signoff.
📚 5. Dense Neural Vector RAG & OCR
Local document ingestion pipeline supporting technical PDFs and scanned manuals. Local Tesseract OCR extracts text; SentenceTransformers generates 384-dim embeddings stored in embedded Qdrant for semantic search.
🕸️ 6. Causal GraphRAG Knowledge Engine
Traverses topological relationships (HAS_COMPONENT, EXHIBITS_SYMPTOM, CAUSED_BY, RESOLVED_BY) across machinery, historical breakdowns, and maintenance logs to uncover non-obvious root causes.
🔄 7. 6-Node LangGraph Orchestrator
Cyclic state-machine coordinating structured task planning, dynamic sub-agent dispatch, evidence evaluation, bounded replanning (max 2 retries), human safety gates, and final grounded answer synthesis.
💬 8. Multi-Turn Working Memory
Persists dialogue turns in SQLite. Injects the last 10 turns of conversational context into prompt buffers, allowing engineers to ask context-aware follow-up diagnostic questions across extended shifts.
📦 9. AST-Restricted Python Sandbox
Executes data analysis and curve-fitting scripts in memory. Uses Python Abstract Syntax Tree (AST) validation to strictly block os, sys, socket, open, eval, and exec system calls.
⛓️ 10. Chained HMAC SHA-256 Audit Trail
Every machine alert, E-Stop trip, approval signoff, and login is cryptographically hashed with the preceding entry's hash. The /api/audit/verify endpoint validates log chain integrity, making tampering impossible.
